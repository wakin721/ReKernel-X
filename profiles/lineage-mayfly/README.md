# LineageOS Xiaomi 12S profile

This profile applies only to `mayfly`, kernel `5.10.260-gki-gef362912d37b`,
with the exact `kernel.config` recorded here. The reference system was
`23.2-20260925-NIGHTLY-mayfly`. It is not a general Android 12/13 GKI profile.

## Provenance

- `kernel.config`: decompressed `/proc/config.gz` from the reference device.
- Kernel source: LineageOS/android_kernel_xiaomi_sm8450 at
  `ef362912d37b761041709638c1e571d6394e9558`.
- `Module.symvers`: 14,600 core kernel exports reconstructed from the running
  device's boot kernel export/CRC tables, not a table generated by `modules_prepare`.
  `vmlinux-to-elf` 1.3.6 reconstructed the symbol-bearing ELF; the extractor is
  `ci/mayfly/extract_symvers.py` (requires pyelftools).
- Cross-check: all 101 core-kernel CRC imports in the device's loaded
  `coresight-tmc.ko` matched this table; its other 33 imports refer to other modules.
- Compiler: Android Clang r563880c, build 14054515, matching the kernel banner.
  The immutable prebuilt repository commit is in `profile.json`.
- Hashes in `profile.json` are checked before every build. No raw boot image,
  device identifier, application data or device logs are included.

The kernel uses PREL32 export records but direct 32-bit CRC records. The extractor
handles those separately, validates the Linux banner, record sizes, symbol names,
sort order, namespaces and nonzero CRCs. The extraction is specific to this kernel;
it is not a generic boot-image processing pipeline.

## Compatibility

The stock android12-5.10 module required the unavailable `__stack_chk_guard`.
The reference kernel uses per-task stack protection. An android13-5.10 prebuilt
loaded but caused freezes on this device; loading alone does not prove matching
Binder internals or hook signatures. The custom build copies LKM-Source into the
matching kernel tree so its relative Binder headers come from that exact source.

CFI, full LTO, per-task stack protection and MODVERSIONS remain enabled. Every
imported CRC and `module_layout` must match the table, and `__versions` must be
nonempty. The three permitted *new* config entries are the successful compiler
link probes and disabled UAPI header test; changing existing entries fails CI.

The original local build from upstream 1.6 passed reboot/automatic loading,
NoActive's `ReKernel-X通知正常` log and interactive use without freezes. A new CI
artifact is not automatically device-tested. CRCs cover exported interfaces;
they do not prove all internal hooks or runtime behavior are correct.

After a kernel/ROM update, collect and review the new source, config, compiler
and export CRCs and make a new profile. Do not edit vermagic, remove `__versions`,
disable CFI or relax the installer checks to force a mismatch to load.
